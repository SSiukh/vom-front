# Інструкція для дизайну — VOM Systems

**Style preset:** `--preset b1aKQdk7k`

> Застосовувати цей пресет стилю до всіх екранів нижче: колірна палітра, типографіка, форма компонентів (радіуси, тіні, відступи) мають бути єдиними у всій системі.

---

## Загальний контекст продукту

VOM Systems — адміністративна панель для управління замовленнями, товарами та витратами з інтеграцією Нової Пошти (автостворення ЕН). Аудиторія — внутрішні оператори/менеджери. Тип інтерфейсу: **B2B admin dashboard**, щільна інформація, багато таблиць та форм, функціональність важливіша за декоративність.

**Загальна навігація:** лівий сайдбар (згорнутий/розгорнутий стан), хедер зверху, футер знизу. Розділи сайдбару: Замовлення, Товари, Витрати, Таблиця (CRM), Дашборд, Відправники, 2FA.

---

## 1. Глобальні компоненти

### Хедер
- Логотип зліва
- Праворуч: логін користувача + іконка виходу (тільки для авторизованих)
- Мінімалістичний, тонкий, не перевантажений

### Лівий сайдбар
- Два стани: згорнутий (тільки іконки) / розгорнутий (іконки + текст)
- Кнопка згортання/розгортання зверху
- 7 пунктів меню з іконками: Замовлення, Товари, Витрати, Таблиця, Дашборд, Відправники, 2FA
- Hover-ефект на кожному пункті + виділений активний стан (колір з пресету)
- Приховано на сторінці входу

### Футер
- Логотип + текст "© 2026 VOM"
- Тонкий, малопомітний

## 2. Сторінка входу
**Layout:** центрована картка форми на нейтральному фоні, без сайдбару/хедера
- Поле логін
- Поле пароль (з іконкою ока для показу/приховування)
- Кнопка «Увійти» (primary)

## 3. Сторінка 2FA
**Layout:** центрована картка, повноекранний фокус (інші розділи заблоковані до завершення)
- QR-код по центру
- Секретний ключ під ним (текст для копіювання)
- Поле вводу 6-значного коду
- Кнопка «Підтвердити»
- Список кодів відновлення + кнопка «Скопіювати»
- Індикатор статусу 2FA (badge: налаштовано / не налаштовано)

## 4. Сторінка замовлень
**Layout:** стандартний список-сторінка
- Хедер сторінки: заголовок + кнопка «Створити замовлення» (primary, справа)
- Панель фільтрів: діапазон дат (від/до), тип (Кастомний/Сталий), дата
- Таблиця замовлень (рядки клікабельні → деталі)
- Пагінація знизу (від 10+ записів)

## 5. Сторінка створення замовлення
**Layout:** двокроковий wizard/степер (Відправлення → Адреса)

**Крок 1 — Відправлення:**
- Селект типу відправки
- Динамічний масив товарів (картки, що додаються), кожна картка:
  - Тип товару (селект) → Товар (пошук-селект) АБО Ціна (якщо кастомна наклейка)
  - Фото товару (превʼю)
  - Кількість, Вартість (readonly/розрахункове)
  - Чекбокс «Акційна ціна» (умовний)
- Загальна вартість замовлення (виділена, зверху або збоку — sticky)
- Тип оплати (селект) → умовне поле «Часткова вартість»

**Крок 2 — Адреса:**
- Блок «Відправник» (readonly інформація)
- Селект адреси відправки
- Форма отримувача: телефон, прізвище, ім'я, по батькові
- Радіогрупа «Куди доставити»: Відділення / Адреса / Поштомат
- Умовні поля залежно від вибору (населений пункт + відділення / вулиця+будинок+квартира / поштомат)

**UX-нюанс:** позначити крок степера, кнопки «Назад»/«Далі», фінальна кнопка «Створити»

## 6. Сторінка деталі замовлення
**Layout:** readonly-версія форми замовлення (структуровані блоки інформації)
- Кнопки «Редагувати» та «Видалити» у верхньому правому куті (Видалити — деструктивний стиль, з підтвердженням)

## 7. Сторінка редагування замовлення
- Та ж структура, що й деталі, але поля редаговані (там де дозволяє API Нової Пошти — інші задизейблені/заблоковані з поясненням)
- Кнопка «Зберегти» (primary, sticky знизу або зверху)

## 8. Сторінка товарів
**Layout:** список-сторінка
- Хедер: заголовок + кнопка «Додати товар»
- Фільтр «Тип товару» (Наклейка/Брелок)
- Таблиця/грід товарів: Фото, Тип, Назва, Ціна, Акційна ціна, Кількість на складі
- Пагінація

## 9. Сторінка створення/редагування товару
**Layout:** проста форма (можна в модалці або окремій сторінці)
- Тип товару (селект)
- Назва
- Завантаження фото (drag&drop зона)
- Ціна, Акційна ціна (опційно)
- Кількість на складі
- Кнопка «Зберегти»

## 10. Сторінка деталей товару
- Картка з фото + структуровані дані
- Кнопки «Редагувати» / «Видалити»

## 11. Сторінка витрати
**Layout:** список-сторінка
- Хедер: заголовок + кнопка «Внести витрату»
- Таблиця: Тип витрати, Назва (умовно), Вартість, Дата, Дії (редагувати/видалити)
- Пагінація

## 12. Сторінка внесення/редагування витрати
**Layout:** компактна форма (модалка або окрема сторінка)
- Тип витрати (селект)
- Назва (умовне поле, тільки якщо тип «Інше»)
- Вартість
- Кнопка «Зберегти»

## 13. Сторінка CRM таблиці
**Layout:** widescreen data-table сторінка (максимум горизонтального простору)
- Панель фільтрів зверху: діапазон дат, сортування від/до, тип товару, статус відправлення
- Широка таблиця з колонками: Дата створення, № накладної, Тип оплати, ПІБ отримувача, Телефон, Вартість, Статус (badge з кольором за статусом), Тип товару
- Статус — кольоровий бейдж (напр. зелений — доставлено, синій — відправлено, червоний — відмовлено, сірий — отримано)
- Sticky-рядок «Усього» знизу таблиці із загальною вартістю
- Пагінація

## 14. Сторінка дашборду
**Layout:** grid аналітичних віджетів
- Фільтр періоду зверху (date range picker)
- Ряд карток-метрик (4 шт в ряд на desktop): Загальний дохід, Загальні витрати, Прибуток, Кількість замовлень — кожна з іконкою та великим числом
- Лінійний графік «Дохід по днях» (широкий блок)
- Кругова діаграма «Витрати по категоріях»
- Кругова діаграма «Статуси відправлень»
- Графіки — у 2 колонки на desktop, стек на mobile

## 15. Сторінка відправники
**Layout:** список-сторінка
- Хедер: заголовок + кнопка «Внести відправника»
- Таблиця: ПІБ, Номер телефону, Статус, Дії
- В рядку: чекбокс «Активний» (radio-поведінка — лише один активний), кнопка «Оновити дані», кнопка «Видалити» (з підтвердженням)
- Пагінація

## 16. Сторінка внесення відправника
**Layout:** проста форма
- Поле «API ключ»
- Кнопка «Перевірити»
- Після перевірки — readonly поля ПІБ та Номер телефону (підтягнуті)
- Кнопка «Зберегти» (активна лише після успішної перевірки)

## Загальні UX-принципи для всіх екранів
- Використовувати консистентні компоненти: таблиці, картки-метрики, бейджі статусів, форми з умовною видимістю полів
- Деструктивні дії (видалення) — завжди з модальним підтвердженням
- Порожні стани (немає замовлень/товарів/витрат) — дизайн заглушки з іконкою + текстом + CTA
- Адаптивність: сайдбар згортається в іконки на планшеті, таблиці — горизонтальний скрол на мобільному
- Усі стани форм (readonly / editable / disabled) мають бути візуально розрізнювані
